# DEO CORE Backend

Django 5.2 LTS, Django REST Framework, Jazzmin. Точные версии зависимостей зафиксированы в `requirements.txt`.

## Локальный запуск

Python 3.13 или 3.14. Из корня проекта:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py seed_content
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8000
```

Для локальной разработки SQLite используется автоматически. В `.env` можно оставить `DATABASE_URL` пустым. Секреты, база, загрузки и окружение не включаются в Git.

- Админка: http://localhost:8000/admin/
- API: http://localhost:8000/api/site/
- Swagger: http://localhost:8000/api/docs/
- OpenAPI: http://localhost:8000/api/schema/
- Health: http://localhost:8000/api/health/

`seed_content` переносит существующий контент сайта и места под шесть логотипов в CMS. Повторный запуск не перезаписывает редакторские изменения. Команда также создаёт группы «Редакторы сайта» и «Менеджеры заявок».

Альтернатива интерактивному `createsuperuser` **только для локальной разработки**: `python manage.py create_local_admin`. Она создаёт пользователя `admin` со случайным паролем и сохраняет доступ в исключённом из Git файле `.local-admin.txt` с правами `0600`. Повторный запуск не меняет пароль. В production команда запрещена.

## Подключение фронтенда

В другом терминале, из корня проекта:

```bash
npm install
npm run dev:full
```

Или задайте `NEXT_PUBLIC_API_URL=http://localhost:8000/api` в `.env.local` и запустите `npm run dev`. В production укажите публичный **HTTPS** URL Django; при общем домене через Nginx используйте `/api`.

`NEXT_PUBLIC_API_URL` встраивается во фронтенд во время сборки. После изменения значения нужна новая сборка. Без этой переменной сайт работает автономно, форма скачивает бриф.

Подключённая версия читает проекты, услуги, этапы, партнёров, статьи, стек, первый экран и контакты из `/api/site/`. Новые кейсы и статьи доступны через `/projects/?slug=...` и `/insights/?slug=...` без пересборки статического фронтенда. Предсозданные адреса старых кейсов сохраняются. Метаинформация HTML и sitemap статического сайта формируются при сборке; для динамического серверного SEO нужен серверный Next.js либо отдельная сборка с CMS-данными.

## Jazzmin и роли

В админке доступны:

- Настройки: первый экран RU/EN, контакты, поля SEO.
- Проекты: slug, категория, индустрия, обложка, описание, задача, решение, результат, статус, теги, языковые версии.
- Услуги, этапы работы, партнёры и логотипы.
- Статьи, команда, технологии, отзывы, вакансии, статистика.
- Заявки: статус, ответственный сотрудник, внутренние заметки, UTM/referrer и приватные вложения.
- Очередь доставки в CRM.

Запись видна в публичном API только при включённом «Опубликовано». Будущие статьи скрыты до даты публикации. Редакторы управляют контентом; менеджеры просматривают заявки и меняют статус, ответственного и заметки. Права назначаются сотрудникам (`is_staff`) в `/admin/auth/user/`. Команда `bootstrap_roles` восстанавливает стандартные права групп. Только суперпользователь по умолчанию управляет пользователями и группами.

Модели команды, отзывов, вакансий и статистики доступны через API и CMS; отдельные новые интерфейсные блоки для них пока не добавлены. В текущий сайт подключены уже существующие секции.

## API

Все адреса заканчиваются `/`. Списки постраничные: `count`, `next`, `previous`, `results`, по 20 записей. `/api/site/` отдаёт опубликованный контент главной одним объектом, без пагинации. Контент возвращается сразу с RU/EN полями; точные имена доступны в OpenAPI.

| Адрес                                     | Методы | Назначение                                           |
| ----------------------------------------- | ------ | ---------------------------------------------------- |
| `/api/site/`                              | GET    | Контент главной                                      |
| `/api/settings/`                          | GET    | Контакты, первый экран, SEO                          |
| `/api/projects/`                          | GET    | Проекты; `?category=Web&industry=Finance&search=...` |
| `/api/projects/{slug}/`                   | GET    | Кейс                                                 |
| `/api/services/`                          | GET    | Услуги                                               |
| `/api/process/`                           | GET    | Этапы                                                |
| `/api/partners/`                          | GET    | Партнёры                                             |
| `/api/articles/`, `/api/articles/{slug}/` | GET    | Статьи                                               |
| `/api/team/`, `/api/technologies/`        | GET    | Команда и стек                                       |
| `/api/testimonials/`, `/api/statistics/`  | GET    | Отзывы и показатели                                  |
| `/api/jobs/`, `/api/jobs/{slug}/`         | GET    | Вакансии                                             |
| `/api/project-request/`                   | POST   | Заявка на проект                                     |
| `/api/contact/`                           | POST   | Обращение                                            |

Публичное API не разрешает изменять контент, просматривать список заявок или получать их вложения.

### Заявка

JSON либо `multipart/form-data`, если есть файл:

```json
{
  "name": "Имя",
  "email": "person@example.com",
  "company": "Компания",
  "contact": "@telegram",
  "projectType": "Website",
  "description": "Описание задачи, минимум 10 символов.",
  "budget": "estimate",
  "timeline": "flexible",
  "consent": true,
  "locale": "ru",
  "utm_source": "campaign",
  "request_id": "f5f860ea-903d-4bad-9a57-fbb41e251a65"
}
```

Для `/api/contact/` можно отправить `message` вместо `description` и не указывать `projectType` — будет выбран `Other`. Имя, email, описание/сообщение и согласие обязательны. Поля статуса, источника, ответственного и внутренних заметок не принимаются извне.

`projectType`: `Mobile App`, `Website`, `Web App`, `CRM`, `UI/UX`, `Automation`, `Other`.

`budget`: `estimate`, `under-1000`, `1000-3000`, `3000-5000`, `5000-10000`, `10000-plus`.

`timeline`: `flexible`, `asap`, `1-2 months`, `3-6 months`.

Повторная отправка с тем же `request_id` не создаёт второй лид. После `201` возвращается только идентификатор и подтверждение. При ошибке возвращаются `message` и `errors`; `400` — валидация, `403` — запрещённый Origin, `413` — размер запроса, `429` — лимит частоты. Лимиты: 5 отправок в минуту, 30 в сутки на адрес источника. Honeypot `website` должен оставаться пустым.

### Файлы

Вложения заявок: PDF, DOCX, UTF-8 TXT, до 5 MB. Проверяется содержимое, а не только расширение. Вложения хранятся в `private_uploads`, отдельно от публичных изображений. Скачать их можно только через защищённый адрес админки с правом `view_lead` или `change_lead`; прямых публичных URL нет.

Публичные изображения CMS: PNG, JPG, WEBP и статичные SVG. Активное содержимое SVG и внешние ссылки отклоняются. В production файлы из `media` отдаёт Nginx; `private_uploads` не монтируется в веб-контейнер. Валидатор не заменяет антивирусную проверку вложений: при её необходимости добавьте отдельный сервис.

Удаление записей Django по умолчанию не очищает файловое хранилище. Срок хранения заявок, политика удаления файлов и резервных копий задаются перед рабочим запуском.

## CRM webhook

Заявки всегда сначала сохраняются в Django. При заполненном `CRM_WEBHOOK_URL` в той же транзакции создаётся запись очереди. Ошибка внешней CRM не теряет заявку и не превращает принятую заявку в ошибку для посетителя.

```bash
python manage.py process_crm_queue --limit 20
```

Запускайте команду по расписанию или включите Docker-профиль `crm`. До настройки интеграции сетевые обращения не выполняются. Старые заявки можно добавить в очередь действием в админке. Уже доставленные записи этим действием не отправляются повторно.

Контракт webhook — JSON с полями заявки в `snake_case`, `id`, `created_at`, `source=Website`, UTM, referrer и согласием. Вложение передаётся как `attachment: {name, contentBase64}`. Заголовки: `Authorization: Bearer ...` при настроенном токене и `Idempotency-Key` с UUID заявки. Получатель должен обрабатывать этот ключ идемпотентно и отвечать `2xx`. Перенаправления отклоняются, допустим только HTTPS. Это универсальный адаптер: формат существующей DEO CORE CRM нужно согласовать с её API, прежде чем включать интеграцию.

До 5 попыток с увеличением паузы. Статус и последняя ошибка видны в Jazzmin. На PostgreSQL воркеры используют блокировку строк `skip_locked`; для SQLite запускайте только один воркер. Тесты не отправляют данные во внешние сервисы.

## PostgreSQL, Docker и размещение

Из корня проекта:

1. Создайте `backend/.env` из примера. Заполните `POSTGRES_PASSWORD` случайным URL-safe значением.
2. Для общего домена соберите фронтенд: `NEXT_PUBLIC_API_URL=/api npm run build`.
3. Выполните `docker compose --env-file backend/.env up --build -d`.
4. Выполните `docker compose --env-file backend/.env exec api python manage.py seed_content`.
5. Создайте администратора: `docker compose --env-file backend/.env exec api python manage.py createsuperuser`.

Локальная Docker-версия: http://localhost:8080. Наружу привязан только `127.0.0.1:8080`; PostgreSQL, Redis и Gunicorn доступны внутри Docker-сети. Переменная `DATABASE_URL` в Compose переопределяется на PostgreSQL. Секрет PostgreSQL должен быть URL-safe, поскольку входит в URL подключения.

Это конфигурация для локальной проверки и основа размещения. Для рабочего сервера: настройте TLS в Nginx, `DJANGO_DEBUG=false`, сильный `DJANGO_SECRET_KEY`, реальные `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS`, `CORS_ALLOWED_ORIGINS`, `FRONTEND_URL`. Пример Nginx сейчас слушает HTTP 8080; при `DEBUG=false` без TLS будет перенаправление на HTTPS. Завершайте TLS в этом Nginx, чтобы `$scheme` передавался в Django корректно, либо адаптируйте доверенную proxy-цепочку. Не включайте доверие к заголовкам от произвольного клиента.

Профиль CRM: `docker compose --env-file backend/.env --profile crm up -d`. Он требует настроенных `CRM_WEBHOOK_URL` и при необходимости `CRM_API_TOKEN`.

Тома: `postgres_data`, `public_media`, `private_uploads`, `staticfiles`. Резервируйте PostgreSQL и оба хранилища изображений/вложений. Redis содержит только кэш ограничения частоты.

Текущий хостинг Sites запускает статический фронтенд; Python/Django на нём не запускается. Для подключения опубликованного сайта нужен отдельный сервер Django с HTTPS и разрешённым Origin сайта, затем новая сборка фронтенда с его URL.

## Проверки

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test studio.tests
python manage.py spectacular --file openapi.yaml --validate --fail-on-warn
```

Миграции включены в репозиторий. Тесты создают отдельную временную БД и временные каталоги вложений; локальные данные не удаляются.
